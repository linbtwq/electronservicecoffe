# electronservicecoffe

Веб-приложение для сотрудников. Работа с точками, показаниями счетчиков, остатками, заказами, отгрузками и примечаниями. Данные и документы приложение получает от HTTP-сервиса 1С.

## Запуск

Это статическое приложение без шага сборки и без внешних npm-зависимостей. Открывайте проект через локальный HTTP-сервер. Сервис-воркер не работает при открытии `index.html` как файла. Для входа и загрузки данных нужен доступ к настроенному сервису 1С.

Адрес сервиса по умолчанию задан в `javascript/config.js`. Для локальной проверки его можно переопределить в консоли браузера.

```js
localStorage.setItem('apiBaseOverride', 'https://your-host/path/to/service');
location.reload();
```

Чтобы вернуться к адресу по умолчанию, удалите ключ `apiBaseOverride` из `localStorage` и перезагрузите страницу.

## Структура

### Точка входа и настройки

- `index.html` содержит разметку приложения, подключает стили и загружает классические JavaScript-файлы в фиксированном порядке.
- `javascript/config.js` задаёт адрес API, таймауты, параметры блокировки и размер страниц.
- `javascript/auth.js` восстанавливает сессию и управляет входом и выходом.
- `javascript/core/` содержит ядро. утилиты, хранилище, сеть, очередь, блокировки и глобальное состояние.
- `javascript/ui/` содержит интерфейсные помощники. иконки, тосты, статус связи, диалоги, тема и работа с фокусом.
- `javascript/features/` содержит рабочие сценарии. поиск, карточки, показания, оплата, остатки.
- `javascript/app/` содержит сборку приложения. загрузка, синхронизация, события, обновление и запуск.
- `javascript/optimize.js` добавляет небольшие оптимизации интерфейса.

### Функциональные модули

- `javascript/assortments.js` показывает ассортимент точки и оформляет заказ пополнения.
- `javascript/recount.js` оформляет перерасчет фактических остатков.
- `javascript/notes.js` создает примечания и показывает историю.
- `javascript/goods.js` загружает и ищет номенклатуру в боковой панели.
- `javascript/drawer.js` управляет боковой панелью и сведениями о пользователе.
- `javascript/machines.js` показывает и фильтрует остатки по автоматам.
- `javascript/shipment.js` оформляет отгрузку товаров со склада на точку.

### Стили и офлайн-режим

- `style.css` задаёт базовые стили и подключает `css/modals.css` и `css/ui.css`.
- `css/mobile.css` содержит адаптивные правила. `css/theme.css` подключается последним и переопределяет визуальные токены и компоненты.
- `sw.js` кеширует оболочку приложения и обслуживает запросы при отсутствии сети. API-запросы 1С намеренно не кешируются.
- `version.js` задаёт версию приложения, по которой сервис-воркер именует кеш.
- `manifest.json` содержит метаданные устанавливаемого веб-приложения.

## Порядок загрузки

JavaScript подключается обычными тегами `<script>`, без модульной системы. Порядок в `index.html` важен. `version.js` и `config.js` задают конфигурацию до потребителей. Ядро в `javascript/core/` объявляет общие функции и состояние, которыми пользуются функциональные модули.

При добавлении или переименовании файлов обновляйте также список `ASSETS` в `sw.js`. Иначе новая версия может не загрузить файл в офлайн-кеш.

При выпуске измените `APP_VERSION` в `version.js`, чтобы браузер создал новый кеш. Если изменён порядок скриптов или ресурсов, проверьте запуск через локальный HTTP-сервер и основные сценарии с доступным тестовым сервисом 1С.

## Соглашения по коду

- В начале исходного файла кратко указаны его назначение, ответственность и важные зависимости.
- Большие файлы делятся на пронумерованные смысловые блоки. Комментарии объясняют границы ответственности и неочевидные правила, а не пересказывают каждую строку.
- Стили остаются разделенными по назначению. Учитывайте порядок каскада. Сначала `style.css`, затем мобильные правила, затем финальные переопределения темы из `index.html`.
- В `manifest.json` комментарии недопустимы по формату JSON. Его назначение описано здесь, в README.
